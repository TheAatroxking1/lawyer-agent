# 面试演示版合同 Agent 设计

## 目标

把当前合同审阅能力整理成一条可以现场展示、可重复运行、不会因为一次模型调用失败而失去演示价值的主线：登录后进入 ChatGPT 风格工作台，上传或选择演示合同，看到两次 Qwen 多模态调用、动态 MCP 工具发现、第二版 RRF＋rerank 检索、法律证据和网页批注，完成后仍能在同一个会话里自然追问。

## 范围

- 在合同审阅结果中持久化一份安全的 MCP 工具目录快照。目录只包含工具名、能力、说明和发现/授权状态，不包含输入 Schema、凭据、用户内容或隐藏 Prompt。
- 在审阅进度和结果中展示工具调用链、检索证据和可复核的法律原文，让面试官能解释 Agent、MCP、RAG 和批注之间的关系。
- 增加演示模式。演示模式使用项目内置的合成合同和固定的、已脱敏的审阅结果，按真实流程节奏播放阶段，不调用 Qwen、RAG、数据库外部法律服务或客户文件；仍要求用户登录并受当前租户会话约束。
- 真实模式保持现有 PDF 上传和合同审阅行为；演示模式与真实模式明确标识，不能把固定结果伪装成真实模型结果。
- 在合同审阅页面提供工具目录抽屉/面板，显示动态发现的合同文档工具和法律研究工具；允许从结果页继续普通对话，继续使用已有会话、租户和合同上下文。
- 维持现有法律证据门禁：引用展示为证据草稿，不能将演示或未经律师复核的结果表述为正式法律意见。

## 非目标

- 不在本切片内重写通用 MCP Gateway 的授权模型，不把动态发现误认为动态授权；工具登记、租户权限和二次授权继续由现有服务控制。
- 不新增真实法律语料、客户 PDF、模型 Key 或生产数据。
- 不把全部 JSON Schema 暴露给网页，不展示内部推理过程，不改变现有两次 Qwen 调用边界。
- 不修复项目状态文档中已经记录的历史测试基线问题，不把演示模式当作生产部署或法律质量验收。

## 架构与数据流

```text
登录/租户
   ├─ 演示模式 → 固定合成 PDF + 固定结果 + 有界阶段动画
   └─ 真实模式 → PDF 上传 → Qwen 总结 → MCP list_tools 动态发现
                         → 第二版 RRF + rerank → Qwen 审阅
                         → 证据门禁 → 保存批注与工具目录快照
结果页：风险草稿 + 法律片段 + 工具目录 + PDF 坐标批注
                              ↓
                         同会话普通追问
```

真实运行在 runtime 装配完成 MCP Client 后，从远端 `list_tools` 产生工具目录，再随 evidence manifest 保存。公共 HTTP 投影只返回有界字段；历史记录没有目录时返回空数组，兼容既有数据。

演示模式使用独立的应用服务/响应模型，返回与 `ContractRunView` 相同的安全投影和演示标记。固定结果必须包含至少两处问题、两条法律证据片段、一个可点击批注和完整的 MCP 工具目录。演示服务不得调用真实模型或检索客户端。

## 页面行为

- 欢迎页增加“运行演示合同”入口；点击后显示“演示模式”标签和阶段时间线。
- 真实或演示结果都显示：审阅摘要、风险数量、证据片段、工具目录按钮、查看 PDF 原文按钮。
- 工具目录中按能力分组展示“已发现/已授权”状态，说明动态发现来自 MCP Server；不显示 schema 内容。
- 点选 PDF 标红或触摸标红，只显示该意见的修改建议；法律原文仍在中间结果卡片中。
- 普通追问沿用当前会话消息接口。追问失败时显示稳定错误，不清空已经完成的审阅结果。

## 失败与兼容

- 演示 fixture 损坏或服务返回未知状态时，返回稳定的 `demo_fixture_unavailable`，不退化为真实模型调用。
- 旧运行的 `evidence_manifest` 没有 `mcp_tools` 时视为空目录；旧结果、状态和引用不变。
- 工具目录超出有界长度时截断并记录质量警告；单项名称、能力和说明均有长度上限。
- 演示结果必须标明 `is_demo=true`，普通对话上下文也保留该标志，防止用户误把演示内容当成真实审查。

## 验收标准

1. 合同 runtime 的动态发现结果可以保存、读取并通过 API/SSE 返回，且旧数据仍能读取。
2. 前端能从登录后的合同页启动演示，看到完整阶段链、工具目录、法律证据、PDF 标红和点击建议。
3. 演示过程中没有 Qwen、RAG、Embedding 或外部法律服务调用，重复运行结果稳定。
4. 真实上传路径的类型、错误、证据门禁和会话追问行为保持通过。
5. 后端聚焦测试、前端测试、类型检查和构建通过；浏览器实际打开 `/chat` 完成一次演示路径。
