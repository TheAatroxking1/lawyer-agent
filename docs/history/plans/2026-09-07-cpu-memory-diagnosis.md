# CPU 向量私有内存增长的有界诊断

已观察事实与停止点见 `.superpowers/sdd/cpu-private-memory-growth-audit-20260907.md`。本计划先验证因果线索，不预设 PyTorch、线程或 OpenSearch 是唯一根因。

## 约束

- GPU 计算继续暂停，当前无模型任务；每次仅一个 CPU 模型进程。不得用无限重启绕过内存增长。
- 不更换权重、模型身份、维度、归一化和文本覆盖策略，不写业务库、索引或原件。实验使用合成文本，不把实验向量写入真实缓存。
- 每组最多 32 次串行模型调用、每次一条短合成文本，4 CPU 线程、window 1；单组最长 120 秒，进程私有提交量达到 6 GiB 或可用物理内存低于 2 GiB 时停止。启动前至少 4 GiB 可用物理内存。
- 每组退出后确认实际进程关闭，不能以等待超时当作模型线程已终止。保留原配置、失败报告与缓存。

## Task 1：对照证据

首组恒定短文本 32 次：每调用新线程组首/末私有内存 2539.40/2578.13 MiB（+38.73），复用组 2540.77/2540.77 MiB（+0）；两组向量完全一致，分别 32/1 个 native thread，均退出且无 CUDA。该差异不足以解释 30 GiB 长任务增长，因此继续独立的变长合成组：16/32/64/96/128/192/256/384 字循环，共最多32次，每次仍一条，保留同样时间/内存停止线。不得把首组差异直接当作根因证明。

- [x] 使用同一冻结模型和同一输入，比较当前每调用新线程的执行器与单一复用线程的只读诊断路径。记录模型加载前后、每次完成后的 PrivateUsage/WorkingSet、native thread ID、耗时和停止原因。
- [x] 每组独立进程，组间核对没有存活模型。对比向量维度、有限值、L2 和数值差异，区分执行线程变化与模型结果变化。
- [x] 条件判定：变长对照显示复用显著减少增长，因此进入 Task 2；无需进入未减少增长时的替代调查分支。四组均正常退出，向量对应一致，但不替代全集长期验证。

## Task 2：有证据后修复

变长32次对照已支持线程复用：原执行器第1/8/16/24/32次私有内存2540.93/2799.09/3070.39/3274.57/3547.19 MiB；复用线程为2542.08/2696.43/2699.74/2699.74/2700.75 MiB，32条对应向量差异为0。两组实际16.17/15.30秒完成，未触发停止线、无CUDA，进程已关闭。报告 `cpu-varied-thread-memory-{per_call,persistent}-20260907.json`。这支持修复当前每调用新线程的行为，但尚不证明生产全集长期稳定。

执行采用独立实现子代理及独立复审。实现范围限定 `infrastructure/providers/embedding_execution.py` 及对应 unit execution/provider/lifecycle 测试；必要的生命周期说明由根代理维护。一个 Runner 惰性创建并复用一个自有 daemon 线程，不使用默认执行器或全局共享池；一个实例最多一个实际 operation，禁止积累等待队列。串行 operation（含模型加载与后续编码）必须在同一线程；操作异常不得永久失去工作能力。保留不同事件循环/等待者的 Future 桥接与失败消费行为。

关闭先禁止新任务，唤醒空闲工作线程退出；有运行任务则等待其实际结束，预算不足返回 false，不放开容量或虚报计算结束；实际结束后工作线程退出。空闲及正常关闭须验证线程确实终止，尚未创建线程的关闭也应直接完成。线程创建失败不得卡住 active 状态。避免在持有状态锁时执行 operation/Future 外部回调，避免关闭/完成之间漏通知或丢任务。不得加入操作系统相关分支或为真实模型修改权重/输出策略。

TDD 至少新增：多个串行 operation 的同一线程身份；异常后同一线程再执行；空闲关闭退出；运行中关闭超时后仍 busy/closed 并最终退出；从未启动的关闭；既有 timeout/cancel/late-failure/loop-closed/start-failure 等测试继续通过。测试不加载真实模型。根代理负责有限 CPU A/B/真实缓存验证与完整后端回归。

- [x] 只有证据支持线程生命周期相关时，再细化并执行 TDD 修复：连续任务复用工作线程；并发立即 busy；取消/等待超时不释放实际计算容量；模型加载和编码均不阻塞事件循环；异常后可再次调用；关闭停止接单且有界排空。
