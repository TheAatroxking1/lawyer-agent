## 查找某个原始文件的切块

打开 `文件清单.csv`，按“原始文件”查找文件名，再查看该行“切块文件绝对路径”。只有 `completed` 行提供已生成文件的位置。清单由 `scripts/build_corpus_delivery_index.py` 根据导出结果生成，失败和待转换的文件也会保留在清单中。

每份来源对应一个稳定标识目录，其中包含：

| 文件 | 内容 |
| --- | --- |
| `chunks.jsonl` | 一行一个 JSON 对象，保存完整条文父块、分层子块或保守回退的段落块，以及来源定位、父子关系和哈希 |
| `paragraphs.jsonl` | 读取到的段落、序号、所属 XML part 及表格单元格位置 |
| `document.json` | 原件路径与 SHA-256、解析版本、块数、质量标记和输出文件哈希；最后写入，作为单文件完成标记 |

JSONL 和 JSON 使用 UTF-8；CSV 使用 UTF-8 BOM，方便在中文 Excel 中打开。

## 确认是否处理完整

根目录 `manifest.jsonl` 逐一记录来源状态：`completed`、`pending_conversion` 或 `failed`；`summary.json` 保存本次导出计数。独立核验结果写入 `verification.json`，重新检查来源集合、原件/产物哈希、文本覆盖、结构、父子关系与精确范围。

全量交付需要当前来源全部处理成功，且全范围独立核验 `complete` 为 `true`、`errors` 为空。试点或允许子集的核验不能代替全量核验。重新导出后应重新运行核验和生成 CSV，避免使用旧报告。

## 定位和质量边界

- 字符范围使用左闭右开区间；`parent_relative_char_span` 相对于父块文本。来源字符范围对应读取后规范化段落文本的拼接位置，不是 Word 二进制文件的字节偏移。XML part、段落序号和 `source_location_status` 一起决定定位范围。
- 保留完整条文父块，因此同时读取父块与子块会出现有意的文本重叠。用于检索时需选择适当叶子，引用时恢复父条文，不能把两者当成互不重复的文档。
- `structure_review_required` 表示未可靠解析法规结构，已保守保留文本，需进一步核对。表格排版、自动编号和图片 OCR 的限制均以 `quality_flags` 记录。机械文本覆盖通过不代表图片内容、法律效力或结论已经专业审核。
- `.doc` 以及实际为旧 Word 容器的文件经受控转换后读取，派生产物放在相邻的 `converted` 目录；原件不改写。`.docm` 只静态读取 XML，不执行宏。
- `legacy_binary_static_text_recovery` 表示受限静态文本恢复，不能当作 Word 正常打开或版式修复成功。`conversion_provenance` 保留恢复版本、策略指纹和原因；原失败记录留在派生目录的 `recovery_origin.json`。隐藏/修订属性的显示状态、版式、图像对象和自动编号不据此恢复，域只保留已有缓存结果、不重新计算。
- 离线 ID 属于 `offline-export-v1`，不是数据库中的 ID。本目录文件完成不代表 MySQL 入库、OpenSearch 发布或生产问答已经验收。
