# Lawyer Agent `AGENTS.md` Design

- 日期：2026-08-31
- 状态：待用户审阅
- 目标文件：仓库根目录 `AGENTS.md`

## 1. 目的

为所有在本仓库工作的 AI 编程代理提供一份精简、稳定、可执行的项目开发宪章。它约束每次开发都必须遵守的产品边界、安全边界、工程流程和验证门禁，但不复制完整架构规格或阶段实施计划。

## 2. 内容结构

正式 `AGENTS.md` 使用以下栏目：

1. 项目使命与适用法域；
2. 权威文档及阅读顺序；
3. 已确认的技术与架构决策；
4. 多租户、隐私及法律证据的不可妥协规则；
5. 代码组织、UTF-8 与 Python 工程规范；
6. 测试驱动开发和完成前验证；
7. Docker、数据库迁移及本地开发安全；
8. 法律数据集的读取、导入与来源保护；
9. Git、变更范围及交付规则；
10. 当前阶段和标准开发命令。

## 3. 关键约束

- 产品仅适用中国大陆法域；不得把境外规则混入法律结论。
- 公网多租户 SaaS 的租户隔离属于安全边界，而非普通业务过滤。
- 法律结论必须绑定可核验的条文、版本、效力状态和来源；证据不足时必须拒答或降级。
- 高风险结果必须进入租户律师或法务人工复核流程。
- LangChain 是首期 AI 主干；LangGraph 仅用于真正需要持久状态、分支或人工中断的流程；MCP 作为受控增强能力，首期核心功能不得依赖具体 MCP Server。
- 禁止提交 `.env`、凭据、验证码、Token、个人信息、客户资料和法律文档原件。
- `F:\ai律师数据库` 是外部只读来源；只按任务需要抽样或导入，不做无目的全量读取，不重复解压 ZIP。
- 所有源代码、配置、文档和测试采用 UTF-8。
- 实现功能或修复缺陷时采用 TDD，并在完成前执行 pytest、Ruff、mypy 及相关 Compose/集成门禁。

## 4. 文档职责与优先级

- `AGENTS.md`：稳定的跨任务开发规则。
- `docs/superpowers/specs/2026-08-31-lawyer-agent-enterprise-architecture-design.md`：产品和企业架构事实来源。
- `docs/superpowers/plans/`：具体阶段的可执行实现步骤。
- 当前代码、迁移和测试：已经落地的行为契约。

发生冲突时，用户当前明确指令优先；随后依次采用已批准规格、当前阶段计划和 `AGENTS.md`。代理不得自行推翻已确认的产品边界或安全要求，应先报告冲突并请求决定。

## 5. 维护边界

`AGENTS.md` 不包含易失的依赖补丁版本、临时任务状态、大段架构说明、供应商密钥或本地环境细节。阶段变化应更新实施计划；只有跨阶段长期有效的规则发生变化时才修改 `AGENTS.md`。

## 6. 验收标准

- 新代理只阅读 `AGENTS.md` 和它指向的当前规格/计划，即可安全开始工作。
- 文档给出可直接执行的开发与验证命令。
- 文档明确禁止跨租户访问、无证据法律结论、敏感信息入库和无目的全量读取数据集。
- 文档长度适中，不重复全局架构正文。
- 不包含 `TBD`、`TODO`、占位符或相互矛盾的规则。
