# S6b3 集合索引有界构建

## 目标和全局约束

S6b2 已完成质量审核接线，但 build_set 累积全集叶子及向量，导航累积全集文档。按总体架构和集合发布全量目标，将新物理索引构建改为有界批次；这是既定全量目标的实现细化，替代旧试点“一次 replace 全部文档”的内存实现，不更改审核、证据或发布协议。

- 保留所有版本预检后才能调用模型或创建/写入主索引的顺序。预检逐版本释放全文，仅保留每版本叶子规范化摘要/数量；第二遍读取必须完全匹配。生产入口仍在同一显式 REPEATABLE READ 事务中检查和构建。
- 主索引每批最多 256 个文档；用户 batch_size 必须为 1..256。每批 embed 后立即 append，不能累计全集向量。内存与单版本图和当前批次相关；不是无限大单文件恒定内存的承诺。
- 新增 append_documents，不删除已写入的其它批次。新索引 PUT 必须确认成功，已存在索引不得复用。HTTP Bulk 单请求不超过 8 MiB，超过则按文档边界拆分，单文档超限拒绝。逐请求校验全部条目确认；不得吞掉部分写入失败。
- 写完主索引后核对实际文档数与预检/写入计数精确一致，失败不建导航、不产生候选。导航采用逐版本预检摘要、逐版本重读一致性验证、最多 256 文档 append，核对完整计数后才能标记 ready。
- 不使用每批 replace/delete-by-query；旧单版本兼容接口保留。任何模型、读取变化、Bulk、计数或导航故障不得进入发布记录/别名切换，可能保留不可发布候选索引，不自动清理。
- 不改真实来源、不调用真实模型、不操作共享 Compose、不写真实 dataset_v1；合成隔离 MySQL/OpenSearch 验证，多批次必须能检索早期与末期数据。
- UTF-8、保留脏工作树、TDD、独立复审；不提交代码。后台服务按归属启动和清理。

## 验证

最终后端 2288 passed / 1 skipped / 1 warning（24.31s），Ruff 全库通过，mypy 205 源文件通过。跳过为平台符号链接，警告为 Starlette/httpx。

专属 MySQL/OpenSearch 集成组合 22 passed（47.96s）。集合用例 2 个合成版本、520 主文档/522 导航，主批次128/导航256，发布后 BM25 返回全部520条并覆盖两版本，审核失配/未知状态与单文件重放仍验证。未调用真实模型或操作真实数据集。

测试已捕获旧实现延迟批次写入、来源重读变化、实际计数缺失和批次无上限；弱引用验证跨版本释放，晚批失败阻止后续模型与发布。Bulk 精确8MiB及+1字节、重复ID、部分确认、完整分片检查均覆盖。导航创建/ready矛盾确认经独立复审发现并完成RED→GREEN修复。

扩大服务样本发现裸阿拉伯/全角条号与序列门禁不兼容，按既有Parser身份增加纯数字分支，仍拒绝零/非法夹杂/重复/漏号/乱序，不改ID；3个实际Parser→Gate契约先RED后GREEN，147组合测试通过并获独立复审。主构建/Bulk、导航也已独立复审通过。

单大版本、真实模型速度、长事务和921,117块全量容量未验收；下一步补齐Embedding生产依赖和模型/镜像验收，不把本切片测试当作全产品完成。
