# document_id 与文书名称映射

用户已确认前一轮提出的“建立文书名称与 document_id 映射”方案，要求先实施此项。该授权覆盖本次独立派生映射及查询入口，不重新讨论已确认方向。

从已导入 Milvus 的 full ready 转换批次读取文书追溯信息，以原文件名去掉最后的扩展名作为 document_name，保留日期、版本、空格和其它文字。名称来源明确标为 source_filename_stem，不冒充核验后的法律正式标题。document_id 使用现有 offline-export-v1 标识，不创建新 ID。

输出独立 document-names/document_names.json（ID到显示名称的对象）及 report.json（来源报告、原清单、追溯文件和输出摘要、计数、同名统计）。使用 JSON 是因为16,006项映射规模可有界加载，方便用户查看与现有Python检索流程使用；本阶段不另建数据库或复制921,117条向量。

提供 DocumentNameMap.lookup、find、enrich，分别按ID查名、按名称找全部候选ID、给检索结果补名称。找不到ID或已有名称冲突时明确拒绝，不猜测，不修改输入记录。同名文书保留多个ID；不会自动挑选某一版本。先核对追溯数据与原始切块manifest的ID/路径/摘要、文档与块数以及已完成导入报告绑定，再原子发布输出；已有输出只核验，不能覆盖不同来源或损坏映射。

验收包括合成负例、16,006项真实映射逐项对照、921,117块来源计数，以及Milvus真实命中结果的名称回填。该映射是本地派生查询文件，本次不会让Attu的现有集合自动新增名称列，也不代表公网RAG接口已接线。
