# Word 转换小批次复用实施计划

> **For agentic workers:** Use subagent-driven-development or executing-plans. 首版安全审查全部通过后才实施；不提交 Git。

**Goal:** 降低 3,179 份 DOC 逐文件启动 Word 的成本，同时保持逐文件结果与有界失败恢复。

**Architecture:** 一个隐藏且可证明归属的 Word 实例只处理有上限的小批次，Python 控制器继续逐文件调用同一转换端口。每次请求/响应都有运行 nonce 和序号；超时仍结束本次 worker 并按现有受控恢复协议清理，已完成产物可续用。默认每实例最多 25 份，不允许无期限保留进程。

**Tech Stack:** 现有 Python 转换 CLI/驱动、PowerShell 5 COM Worker、原子 JSON 请求/响应与恢复日志。

## 2026-09-06 实施与验证状态

Task 1 实现及独立复审通过。批量入口使用独立 `word_batch_worker.ps1`，保留单文件 worker；CLI 通过 `--batch` 启用。新增 journal `accepted_sequence`，只在退出码 0、状态 closed、设置已恢复且请求未接受时，允许一次新实例重试，消除正常空闲退出与新请求的竞态。

已验证：26 份合成文件只启动两个实例；超时、错误响应、中断、密码拒绝、下次运行恢复与空闲退出均保留恢复证据。5 份真实司法解释试点共 18.181 秒（含退出），原件哈希不变；新 idle 竞态实测两个实例共 29.491 秒，最终均恢复设置且无 Word 遗留。独立 P2 复审 11 项通过；该修复后的后端组合 1,568 passed / 1 skipped / 1 warning，Ruff 与 mypy 183 个源文件通过。

Task 2 全量 Word 批次已实际退出：**3,211 成功 / 1 失败**。经文件头识别，候选由原 3,179 DOC 扩为 **3,212 份**（另有 33 份 OLE 容器误用 DOCX 扩展名）；原路径/扩展名不改。唯一失败文件随后按受限静态恢复计划完成；最终16,006份/921,117块独立核验0问题，文件全集交付完成。普通Word与静态恢复继续分开记录。清单为 `artifacts/legal-corpus/converted/manifest.jsonl`，运行日志为 `artifacts/legal-corpus/full-conversion-20260906.log`。Word 普通/诊断与修复试验共 136 份控制日志均确认设置恢复，无遗留 Word。将来运行批次时仍禁止修改 worker/driver 指纹、启动另一 Word 控制器或对相同输出根并发转换。

## Global Constraints

- 继承原切块导出计划的源只读、派生目录隔离、禁宏/链接、原件/产物哈希、Word 用户会话保护与恢复门禁。
- 默认每文件 120 秒超时；批次有文件上限和空闲关闭机制。只杀可证明本次归属且不会关闭用户文档的实例，不按进程名称清理。
- 改动开始前先消除单文件版本独立审查发现的问题；小批次不能绕过缓存版本/路径、文件锁、失败停批或设置恢复。
- 控制器异常退出后仍由下次运行先恢复未完 journal；未恢复前不能新开批次或将结果计为完成。
- 源和输出含中文、空格的路径使用结构化参数/JSON传递，不拼接可执行 Shell 代码。
