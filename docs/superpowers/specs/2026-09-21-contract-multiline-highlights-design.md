# 合同多行标红与精简建议气泡设计

## 目标

合同意见引用跨越相邻行或相邻原生文本块时，每个已核验行都形成独立标红矩形；点击或触摸任一矩形显示同一条意见的修改建议。气泡只展示修改建议，不展示合同原文、问题说明或法律条文，避免遮挡PDF。

## 根因与边界

当前定位器把整页压缩文字用于匹配，却只返回字符数最多的一个块及一个anchor，并用该行覆盖模型的完整quote。因此跨行意见要么完全定位失败，要么只保留首行标红。修复只使用PDF原生文字和坐标，不增加Qwen、OCR或RAG调用，不猜测图片文字坐标。

## 数据与定位

`RiskIssueDraft`保留既有`anchor_id`、`block_id`、`start`和`end`兼容字段，新增有界`highlights`；每项保存`block_id + anchor_id + start + end`，按阅读顺序描述该行实际命中的字符范围。新结果的`quote`始终保留模型输出的完整引用。定位器先在模型页的verified blocks中建立去空白字符索引并要求唯一匹配；模型页码偏移时只接受全文件唯一的实际页。引用含省略号或换行跳段时，可以保存同一实际页内按原文顺序出现的唯一片段，并用`highlights_complete=false`明确表示只标可确认部分；重复文本、跨页拼接、无坐标或覆盖不足均拒绝。Gate按完整或部分模式从各span恢复并核对原文。旧结果未含`highlights`时继续使用单个`anchor_id`。

## 前端交互

前端为`highlights`中的每个合法anchor绘制一个按钮矩形；多个矩形共享同一issue。鼠标点击和触摸点击使用原生button行为，打开同一精简气泡。气泡包含“修改建议”标题和`issue.suggestion`，可关闭；不包含法律引用、合同原文或问题详情。完整审阅信息仍在左侧结果列表显示。

## 旧记录

API读取旧结果时不修改原始事实。当前测试合同可用已保存的原始第二次模型输出恢复完整quote，再通过新版纯定位器生成多行highlights；修复使用独立、可审计的一次性脚本，在事务中校验租户、run、原文哈希和旧结果摘要，生成备份证明后只更新指定run。不能恢复的历史记录仍按旧单anchor或“位置待核对”显示。

## 验证

后端单测覆盖跨块多行、行内起止、重复引用拒绝及单行兼容；Gate覆盖多anchor存在性与quote一致性。前端组件测试覆盖一条意见多个矩形、任一矩形打开同一建议、气泡不出现法律原文。最后对指定23页合同进行无模型调用的修复，在浏览器验证标红、点击/触摸语义和刷新恢复。
