# S6b2 受控集合发布与真实质量检查

依据总体架构 6.1/6.6 和集合发布计划，完成批量导入结果到持久集合发布的入口，并关闭单文件发布绕过质量检查的缺口。上一切片已完成持久发布恢复；本切片不改写已导入语料、不批准真实 pending 元数据。

## 约束与流程

- 只接受完整成功的受控批量导入 JSONL 报告，严格验证 header/file/summary、连续行号、计数、唯一版本、原件/输入/结构 SHA-256、来源与元数据审核引用；预检、部分失败或缺字段报告不得成为发布清单。读取有字节/行/数量上限，不读外部原件，不信任离线 ID。
- 集合 CLI 提供 `--check`：只读数据库，输出自动检查结果、摘要及待专业复核信息，不调用模型、不建索引、不修改别名或发布记录。
- 检查数据库权威版本、元数据、来源证明、全文哈希、条号连续性和分块父链/文本覆盖。禁止把未知缺失字段或未知解析覆盖率写成已通过。缺少效力/日期/类别/地域、缺失证明、静态恢复、损坏或不完整图等自动拒绝；其余质量标记和降级块完整列出供专业审核。
- 对规范化的元数据、证明、条文和块语义、模型/维度/L2、parser、alias 及导入报告哈希生成稳定 SHA-256。重放仅变更 Chunk UUID 时摘要保持稳定；改变内容/关系/配置/质量标记必须改变摘要。
- 真正发布需要自动检查通过、显式人工 `review_ref` 和匹配 `expected_quality_sha256`，不提供强行跳过选项。摘要和审核引用随候选保存到持久发布历史。引用代表操作者提供的审核凭据，代码不能证明专业审核实际完成。
- 检查与构建在显式 MySQL REPEATABLE READ 会话中读取同一事实视图，关闭该读会话后进入独立持久发布事务。来源到全文的外部完整性仍需专业/独立原件核对，不虚构 parse_failures=0 或 coverage=1。
- 单文件入口同样接检查与审核约束；preflight/import-only 保持已有功能。模型始终经 Gateway，发布明确 L2 配置；旧低层兼容服务不能作为生产入口。
- 保留脏工作树；UTF-8；不提交、不重启共享栈、不调用真实模型、不读取全量外部来源。服务验证使用隔离容器、合成来源和向量。
